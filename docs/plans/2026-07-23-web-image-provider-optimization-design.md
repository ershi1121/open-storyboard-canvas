# Web 部署与图片模型配置优化：设计

> 用户已确认采用安全的声明式配置方案；此文档是实现前的冻结设计。

## 目标

让 Web 部署不再因为 Tauri 专属 API 黑屏，并把图片模型配置升级为可组合的声明式 HTTP 模板，同时保留旧配置兼容和 AI 辅助生成草稿能力。

## 方案选择

### 方案 A（采用）：声明式 HTTP 契约

用户通过表单和高级 JSON 配置 URL、方法、鉴权、请求体、图片字段、比例映射、轮询和响应路径；AI 只生成同一份 JSON 草稿。优点是 Web/Tauri 一致、可校验、可脱敏、不会执行任意代码；缺点是厂商签名 SDK 需要后端代理。

### 方案 B：内置供应商适配器扩展

每遇到一家供应商就新增 TypeScript 适配器。短期表单体验简单，但无法覆盖 issue 中的任意字段组合，长期维护和发布成本高。

### 方案 C：执行用户插件

允许粘贴 Python/JavaScript 直接改写请求。表达力最强，但 Web 端需要沙箱/后端执行，存在密钥泄漏和任意代码风险，不适合当前客户端架构。

## 冻结的技术设计

1. 运行时能力集中在 Web/Tauri 边界；TitleBar、启动通知和项目命令均有守卫，Web 项目 CRUD 走 localStorage/内存降级。
2. 图片请求契约为版本化 JSON，支持 JSON、multipart、form-urlencoded、模板变量、图片 single/array/repeat、文生图/图生图分流、比例/分辨率字段映射、同步/异步轮询和多个响应路径。
3. 旧 `extraParams` 字段在读取时归一化，在保存时保留镜像；内置供应商继续使用原有默认映射。
4. AI 配置助手复用已配置文本模型，输出先校验再填入可编辑表单；无文本模型时保留复制提示词/粘贴 JSON 流程。
5. 返回图片实际尺寸与请求比例不一致时只做诊断，不自动反转或重试。

## 验收与回滚

先完成运行时守卫和纯函数契约测试，再接入设置 UI；任一新契约解析失败时回退旧字段路径。所有新增配置均可删除，旧字段和旧 provider ID 不做破坏性迁移；Web 适配器故障只影响浏览器本地存储，不影响 Tauri SQLite。
